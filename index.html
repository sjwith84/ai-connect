Git은 어떻게 움직일까?

파일을 수정하고 → 스테이징하고 → 커밋하고 → GitHub에 올리는 흐름을 버튼으로 따라가 보세요.

① Working Tree

내가 실제로 수정하고 있는 현재 파일 상태.

→

② Staging Area

다음 커밋에 포함할 변경을 선택해 모아두는 영역.

→

③ Commit

특정 시점의 프로젝트 상태를 기록으로 남김.

→

④ Remote

GitHub 같은 원격 저장소에 기록을 공유.

직접 따라하기

시작하려면 「파일 수정」을 눌러보세요.

왜 Commit이 필요한가?

Commit은 단순 업로드가 아니라 프로젝트의 한 시점을 고정하는 기록입니다. 나중에 무엇이 바뀌었는지 비교하고 이전 상태로 돌아갈 기준이 됩니다.

AI와 함께 쓸 때

대화는 설계와 토론에 사용하고, Git 저장소는 현재 코드와 변경 이력을 보존합니다. 채팅창이 바뀌어도 저장소에서 프로젝트 상태를 다시 읽을 수 있습니다.
