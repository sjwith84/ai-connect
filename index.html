Git은 어떻게 움직일까?

Working Tree → Staging → Commit → Remote와 branch → push → Pull Request → merge → pull을 한 흐름으로 이해해 보세요.

① Working Tree

실제로 수정하고 있는 현재 파일 상태.

→

② Staging Area

다음 commit에 포함할 변경을 선택하는 영역.

→

③ Commit

특정 시점의 프로젝트 상태를 Git 기록으로 남김.

→

④ Remote

GitHub에 push하여 다른 작업공간과 공유.

1. 기본 흐름

「파일 수정」부터 눌러보세요.

2. Branch는 어떻게 갈라질까?

main에서 feature branch가 갈라지고 독립적으로 commit을 쌓는 모습을 확인합니다.

3. 다른 작업공간에서 받기

처음 받기GitHub 저장소를 처음 가져옵니다.git clone <repository-url> cd ai-connect
최신 main 받기이미 clone한 작업공간을 최신화합니다.git switch main git pull
원격 branch 확인원격 정보를 받고 branch를 선택합니다.git fetch origin git switch feature/git-branch-demo
main이 merge된 뒤 pull하면 다른 작업공간도 최신 상태가 됩니다.

4. Pull Request → Merge

feature branch를 GitHub에 push하고 PR을 만든 뒤 main에 합칩니다.

feature가 push된 뒤 Pull Request를 만들 수 있습니다.

Branch는 파일 복사본이 아니다

Branch는 특정 commit을 가리키는 이름표에 가깝습니다. 독립적인 commit 흐름을 만들 수 있습니다.

대화는 설계와 토론에, Git은 실제 코드와 버전 이력에 사용합니다. 새 채팅에서도 Markdown과 저장소를 읽어 프로젝트 상태를 복원합니다.
