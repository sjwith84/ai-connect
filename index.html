Git은 어떻게 움직일까?

Working Tree → Staging → Commit → Remote와, branch → push → Pull Request → merge → pull까지 한 흐름으로 이해해 보세요.

① Working Tree

내가 실제로 수정하고 있는 현재 파일 상태.

→

② Staging Area

다음 commit에 포함할 변경을 선택해 모아두는 영역.

→

③ Commit

특정 시점의 프로젝트 상태를 Git 기록으로 남김.

→

④ Remote

GitHub에 commit을 push하면 다른 작업공간에서도 받을 수 있음.

1. 기본 흐름 직접 따라하기

시작하려면 「파일 수정」을 눌러보세요.

2. Branch는 어떻게 갈라질까?

main의 한 commit에서 feature branch가 갈라지고, feature에서 독립적으로 commit을 쌓는 모습을 확인합니다.

3. 다른 작업공간에서는 어떻게 받나?

처음 받는 컴퓨터 GitHub에 있는 repository 전체를 처음 가져옵니다.git clone <repository-url> cd ai-connect
이미 clone한 컴퓨터 원격 main의 최신 commit을 현재 작업공간으로 가져옵니다.git switch main git pull
feature 작업을 받기 원격 feature branch를 가져와 작업을 이어갈 수 있습니다.git fetch origin git switch feature/git-branch-demo
main이 merge된 뒤 pull하면 다른 작업공간도 최신 상태로 이동합니다.

4. Pull Request → Merge

feature branch를 GitHub에 push한 뒤 PR을 만들고 main에 합치는 협업 흐름입니다.

feature가 push된 뒤 Pull Request를 만들 수 있습니다.

Branch는 파일 복사본이 아니다

Branch는 특정 commit을 가리키는 이름표에 가깝습니다. feature를 만들었다고 프로젝트 전체가 별도 폴더로 복제되는 것이 아니라, 독립된 commit 흐름을 가리키게 됩니다.

AI와 함께 쓸 때

대화는 설계와 토론에 사용하고, Git 저장소는 현재 코드와 버전 이력을 보존합니다. 채팅창이 바뀌어도 저장소와 Markdown 문서에서 프로젝트 상태와 설계 의도를 다시 읽을 수 있습니다.
